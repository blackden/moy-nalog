# Заметки по проекту

## Дизайн
- I/O‑bound: сеть доминирует по времени ответа, поэтому фокус на надёжности, ретраях и параллельности.
- `httpx` выбран за поддержку sync/async в одном стиле и удобный API.
- Разделены синхронный и асинхронный клиенты (`ApiClient`, `AsyncApiClient`) для простоты сопровождения.
- Обработка ошибок маппит HTTP статусы на исключения, чтобы вы могли ловить бизнес‑ошибки.
- Константы (enums) вынесены в `constants.py`.

## Ретраи
- По умолчанию: до 2 повторов для 429/5xx, экспоненциальная задержка с джиттером.
- При 401 — сначала попытка refresh токена, затем повтор запроса.

## Валидация
- Модели минималистичны. Если потребуется строгая валидация — можно внедрить pydantic без ломки API.
